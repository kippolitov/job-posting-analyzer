## Things to know

- **Local testing.** Start Azurite from `functions/` with `npx azurite --silent --location .azurite`; stopping it breaks the user lookup ("Authorization check failed"). Local `local.settings.json` has `REQUIRE_AUTH=true`. The extension e2e needs a backend with `REQUIRE_AUTH=false`; `.env.local` wins over environment variables for the `WXT_*` URLs, so swap it and restore it. Extension e2e only runs with `E2E=1`.
- **Build output** is `functions/dist/functions/src/...`. A stale `functions/dist/src/...` from July can mislead scripts.
- **Stopping a background `func start`:** it ignores SIGTERM, use `kill -INT <pid>`.
- **Web app sign-in** is blocked in embedded browsers; use normal Chrome. Direct URL navigation reloads the app and signs out.
- **Production** (read-only queries are fine; ask before changing settings): function app `job-posting-analyzer-func`, storage `jobpostinganalyzer1c79f5`, logs via `az monitor app-insights query --app job-posting-analyzer-insights -g job-posting-analyzer-rg`. Models: free plan has no reasoning effort, Premium `none` on DataZone `gpt-6-luna-premium` at 100K TPM. The production classifier may deny Azure setting changes; give the user the command.
- **Real test postings** come from the job scout (`~/Downloads/job-search-remote-scout/state/followups.tsv`). Greenhouse links in that file open the application form, not the posting; the public text is available from `boards-api.greenhouse.io` by job id.
- **Known limits.** Usage metering counts an analysis if the host kills the worker (PR #32 fixes the model-stall cause). The SC-008 judge run missed by 0.3 points (known limitation, documented). Saved jobs made in the extension appear in the web app only for the same signed-in account; local test accounts are separate.
